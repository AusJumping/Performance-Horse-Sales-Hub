Required architecture
Use a standard Google OAuth 2.0 web server flow for Google Drive.
Create or confirm these backend routes:
•	GET /api/google-drive/status
o	Returns whether the currently logged-in admin/business account has Google Drive connected.
o	Returns connected Google email if available.
o	Returns the current root folder name and root folder ID if configured.
o	Does not return access tokens or refresh tokens.
•	GET /api/google-drive/auth
o	Starts the Google OAuth flow.
o	Uses the app’s Google OAuth Client ID and Client Secret from environment variables.
o	Requests only the minimum Drive scopes needed.
o	Uses access_type=offline and prompt=consent when needed so a refresh token can be issued.
o	Includes secure state validation to protect the flow.
•	GET /api/google-drive/callback
o	Handles the OAuth callback.
o	Exchanges the code for tokens.
o	Stores Sally’s refresh token securely in the database, associated with the correct app owner/business/admin account.
o	Stores connected Google account email if available.
o	Redirects Sally back to the app’s admin dashboard with a success message.
•	POST /api/google-drive/disconnect
o	Disconnects the current Google Drive account.
o	Removes the stored access token and refresh token for that app account.
o	Does not delete generated files from Google Drive.
o	Updates the admin dashboard to show Drive is disconnected.
•	POST /api/google-drive/test
o	Confirms the app can access the connected Drive.
o	Creates or locates the configured root folder.
o	Returns success/failure in plain language.
