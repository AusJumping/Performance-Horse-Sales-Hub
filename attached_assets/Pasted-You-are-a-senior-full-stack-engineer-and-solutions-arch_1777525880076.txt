FORM BACKUP WORKFLOW

2. Generate a canonical JSON snapshot of the submission in the backend
3. Convert that submission into a well-formatted Google Doc
4. File it into the correct folder based on form type
5. Store returned Google Drive metadata in the app database
6. Update submission status to one of:
   - drive_backup_pending
   - drive_backup_complete
   - drive_backup_failed
7. If Drive backup fails, preserve the submission locally, show the failure in admin, and retry safely without creating duplicates

The Google Doc should contain:
- form type
- submission date/time
- record ID
- horse name if applicable
- applicant name if applicable
- all form answers in a clean readable structure
- key uploaded-file references or links if part of the submission
